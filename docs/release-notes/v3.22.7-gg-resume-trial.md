# AI Coding 3.22.7: Claude GG session restore trial

Customer GG sessions now resume through the launcher associated with their
original history directory. The previous implementation recognized the owner
installation but missed `~/.claude-gg-client`, which could route a customer
session through ordinary Claude and show a different login state.

This change recognizes both installations, checks the source file and current
installation binding, and uses that installation's absolute `claude-gg` entry
point. Copied commands also enter the original project directory; an unavailable
directory stops execution. Missing, ambiguous, stale or unsafe launchers do not
fall back to ordinary Claude. No credentials are copied or reset.

## Validation

- Frontend regression suite: 143 files, 1179 tests passed before the final
  whitespace-only formatting correction.
- Rust session suite: 172 passed, 4 explicitly ignored.
- Independent customer GG regression subset: 11 passed.
- Independent execution of copied POSIX commands verified the exact launcher,
  session ID and working directory using inert temporary fixtures, including
  unusual path characters and a missing directory.
- After the formatting correction, the session UI and copied-command tests
  passed again: 50 tests. Type checking passed.
- The installed macOS trial loaded existing sessions and successfully copied an
  owner GG resume command. Installation checks found no changes to protected
  GG/Claude/Codex configuration, system DNS or system proxy, and no restart of
  the existing Claude or Clash core processes.

## Remaining acceptance work

This is a source review branch, not a generally approved release. The full
Harness remains FAIL with `release_allowed: false`. Three existing native
directory-watcher tests timed out during independent execution, although they
passed when the same executable was run in the parent environment. The reason
has not been established. Existing schema/traceability and evidence receipt
gaps are retained rather than treated as passing checks.

Real customer OAuth and terminal session restoration, native Windows behavior
and long-running network continuity have not been accepted end to end. The
macOS trial installer is ad-hoc signed and has no Apple notarization. The local
trial approval does not authorize a general release or automatic customer
updates. Existing public download links are unchanged.

AI Coding session restoration and GG network recovery are separate updates.
This fix does not change GG forwarding policy or guarantee that an upstream
network or API stream can never fail.
